前置传感器是索尼 imx596，相机编号 1。后置传感器是三星 s5kjn1。两路都进图像前端 1（IFE1，Image Front End）。

IFE1 物理地址 `0x0acc3000`，长度 `0xd000`，中断 GICv3 499。  
传感器接口 1（CSID1，CSI Decoder）物理地址 `0x0acc4200`，长度 `0x1000`，中断 GICv3 498。

## 2. 前置通路与尺寸

传感器输出：2592×1952，格式 SBGGR10，数据类 `0x0a`，`0x0114=0x03`（D-PHY，MIPI CSI-2 D-PHY），bin `0x22`，VTS `0x189e`。

媒体链路：

```text
imx596 → CSIPHY4 → CSID1 的 IPP（pad4）→ IFE1 像素口
  → 相机接口（CAMIF，Camera Interface，基址 0x2600）
  → 相机逻辑核（CLC，Camera Logic Core）
  → 写主（WM，Write Master）4 亮度、写主 5 色度
  → 线性 NV12
```

Linux 这一路的输出合同是 Display Full 线性 NV12，2320×1320，步长 4096。  
一帧字节数：

```text
4096 × 1320 + 4096 × 660 = 8110080
```

安卓前置预览的写主读回不是这个合同。安卓写主 4 的图像配置 0 是 `0x07a00a20`（1952×2592），写主 5 是 `0x03d00a20`（976×2592），打包器都是 `0x0000000b`，图像配置 2 都是 `0x00000e00`（3584）。帧增量分别是 `0x006b4000` 和 `0x0035a000`。

## 4. 合格线

前置这一关同时满足才算过：

- `/tmp/pix.nv12` 大于 8110080，对应至少连续非空帧，目标是不少于 3 帧，每帧 8110080 字节。
- 停机时 `dbg1`（相机接口 `0x27f0`）的低 16 位是 `0x8008` 或 `0x8018`。
- 色度值在 128 附近。
- 违例号不是 19。
- 出现第二次相机接口纪元，以及帧结束。

亮度均值不作为这一关的判定。当前伽马模块配置是 1，一帧的亮度均值可以是 0。

后置关的上次测量在内核 `#601`：文件 9331200 字节，3 帧，单帧 3110400，步长 1920（1920×1080）。`#602` 之后没有再跑后置。

应用预览仍走 RDI（Raw Dump Interface，原始旁路）和 CPU 上的 Debayer。前后两关都过之前，预览不切到这条硬件 NV12。

## 9. 根因与修复（`#626`）

### 9.1 观测手段

`#625` 在驱动里加了两样东西：

- 飞行记录器：`dagu_fr_us`（默认 20 微秒）、`dagu_fr_ms`。它在相机接口启动后，用硬中断定时器读顶层调试字 `0x80 0x84 0x88 0x8c 0x9c`…`0xc0`、`0x27f0/0x27f4`、中断状态、写主 4/5 调试和地址状态，只记变化。停流时、关时钟之前打印 `dagu fr` 行。
- 运行时覆盖表：`dagu_ovr`，格式是 `时机:偏移=值,...`，时机有 `init`、`go`、`sof`、`eof` 四种。只允许写 `0x2c` 和 `0x2000`–`0x9ffc`。

顶层调试字每 4 位对应一个模块：位 0 是就绪，位 1 是有效，位 2 是空闲。`5` 是帧间空闲，`1`/`3` 是帧内流动，`2` 是手里有数据、不就绪。

### 9.2 看见什么

`#625` 默认配置下，第一帧帧结束以后，只有 `0xa0` 的第 2、4 个半字节一直是 `1`，整段 23 毫秒的帧间隔都是 `0x55515155`；安卓上是 `0x55555555`。第二帧帧起始后约 40 微秒，这两个位置先变成 `2`，再过约 160 微秒，`0xa0`–`0xac` 一共 16 个位置变成 `2`。相机接口调试字 1 停在 `0x10218000`，没有错误中断。

### 9.3 为什么

`0x4400/0x4600`（驱动里叫 `CLC_CROP`/`CLC_CROP_C`）和 `0x4800/0x4a00`（`CLC_RNDCLAMP_MID_Y/C`）不是显示通路的裁剪和中间钳位，而是人脸检测支路的缩放器和圆整钳位，对应总线写主 8/9（CAF（Code Aurora Forum，高通开源代码库）`cam_vfe480.h` 里的 `VFE_OUT_FD`，`FD_Y`/`FD_C`）。安卓相机 1 的读回可以对上：`0x446c=0xc081999a` 等于 2592/640，`0x4474=0xc0822222` 等于 1952/480，钳位 `0x1df/0x27f`，写主 8 图像配置 0 是 `0x01e00280`（640×480）。

Linux 打开了这条支路，填的却是显示尺寸，而写主 8/9 一直关着。这条支路关不上第一帧，第二帧开始以后它把共用的上游堵住了。

### 9.5 还没解决的

- 竖直方向是 1:1。写主 4 在约第 1336 条输入行就写满了，所以输出是传感器画面上面的 1320 行，没有缩放。水平缩放器相位是 `0xc0200000`，也是 1:1。2320×1320 目前是从左上角裁出来的，不是满视场缩小。
- 画面偏暗（亮度均值约 49），有成块的绿/品红色斑，顶上有一条紫线。这是图像处理参数的问题，和停机无关。
